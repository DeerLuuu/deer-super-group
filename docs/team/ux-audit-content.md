## 0. 结论先行

1. **首次使用路径没有闭合**：Welcome 只有一个“打开工作区文件夹”，不展示模型/Key/Mock 是否就绪，也没有“打开后先做什么”。用户可能进入空对话，点击示例后只得到一条英文内部错误。
2. **产品心智没有建立**：Welcome 用一句话提到 Router 拆任务、成员执行、邮箱/黑板共享，但没有解释 **Router → 任务 → Run → 评审 → 记忆** 的关系；`Run`、`blocker`、`checks`、`head/base` 等词直接进入主界面。
3. **空态已有统一组件，但未全量使用**：任务/邮箱/记忆/聊天空态较好（有 CTA 或示例），但运行面板、上下文、轨迹、评审仍有裸 `.empty` 或“只有说明没有下一步”。
4. **错误文案仍是开发者语言**：`formatError` 只剥掉 Electron IPC 前缀，`member already exists`、`not a directory`、`workspace not found` 等会原样进红色 banner；只有“复制详情/关闭”，没有“下一步”。
5. **设置页是“配置项清单”，不是“配置引导”**：模型页把 Base URL、环境变量、API Key、上下文窗口、最大输出、思考强度平铺；插件/MCP/Skills 用“后端待接入/coming next”占着导航，形成死入口。
6. **渐进披露策略不统一**：关键状态（Key/Mock/预算）没有常驻，低价值说明（Dock 拖动、快捷键、内部实现）反而常驻；高级概念（worktree/checks/handoff）缺少按需帮助。

**建议先做 4 个 P0**：首次就绪清单、Router/Run/评审/记忆关系图（帮助弹层 + 首次引导）、错误文案目录与恢复动作、空态 CTA 全覆盖；再做设置页分组/高级折叠与术语表。

### 1.2 判断口径

- **用户语言**：用户目标/对象/动作，而非实现模块（Dock、Agent Loop、后端、IPC）。
- **可行动**：空态/错误至少有一个明确的下一步；危险动作说明后果。
- **渐进披露**：主界面只放“当前决策所需”；解释性内容按需（帮助、tooltip、展开、设置）。
- **一致性**：同一概念一个中文主词；英文只在首次出现作括注；状态/单位/标点统一。
- **可访问性**：文案不能只靠颜色/图标；错误/状态有文本与 `role`。

## 3. 文案与术语基线（建议）

### 3.1 语气规则

1. **动词开头**：按钮写“创建任务”“运行任务”“打开评审”，不写“确定/提交”。
2. **对象明确**：不写“失败 3”，写“3 个任务失败”；不写“没有选中的 Run”，写“选择一次运行查看详情”。
3. **中文主词 + 英文括注**：首次出现 `Router（协调者）`、`Run（一次执行）`、`blocker（阻断项）`；后续只用中文。
4. **错误三段式**：`发生了什么` + `为什么（可理解）` + `下一步按钮`；原始技术细节放“查看详情/复制”。
5. **说明长度**：常驻 ≤ 2 行；空态 ≤ 2 句；帮助弹层可长，但分“这是什么/我该做什么/进阶”。
6. **不用实现词**：Dock、后端、Agent Loop、IPC、schema、worktree（首次）、checks（首次）、prompt（界面文案）。

### 3.2 建议词汇表

| 概念 | 推荐主词 | 首次括注/说明 | 应避免 |
|---|---|---|---|
| Router | 协调者 | “Router（协调者）：把目标拆成任务并分派” | 只写 Router |
| Run | 一次执行 | “Run（一次执行）：成员对某个任务的一次尝试” | 运行实例、attempt 裸露 |
| 任务 | 任务 | 不解释 | Task（界面） |
| 评审 | 评审 | “合并前检查代码” | review 裸词 |
| 阻断项 | 阻断项 | “blocker：必须解决才能通过评审” | 只写 blocker |
| 检查 | 检查 | “checks：合并前自动跑的测试/构建” | 只写 checks |
| 合并队列 | 合并队列 | 不解释 | MergeQueue |
| 记忆 | 团队记忆 | 下设“共享黑板 / 个人备忘录 / 归档建议” | 黑板=记忆混用 |
| 看门狗 | 预算与异常监控 | 首次帮助解释 hold/handoff/fallback | 直接展示 hold/fallback |
| 投票 decision | 投票结论 | “达到阈值后生成结论并写入黑板” | 只写 decision |
| TTL | 过期时间 | “到期后提醒复核/归档” | 只写 TTL |
| worktree | 隔离工作区 | 首次帮助解释；Git 设置中可保留英文括注 | 主界面裸 worktree |

### 3.3 术语落地顺序

- **P0**：Router、Run、阻断项、检查、合并队列、团队记忆、投票结论；
- **P1**：worktree、handoff/hold/fallback、quorum、TTL、diff/head/base；
- **P2**：内部错误码/事件名（只出现在“详情”）。

## 5. 12 条文案/引导改进

> 优先级：P0=阻断首次成功；P1=明显增加理解/恢复成本；P2=一致性/打磨。每条含证据、建议、放置、示例文案与验收。

### F01 [P0] Welcome 缺“可开始”的就绪检查

- **证据**：`src/App.tsx:2284-2314` 只有品牌、1 句说明、打开按钮；`2498-2512` 导航提示常驻；`2516-2527` footer 才显示 Mock/Key。
- **问题**：无 Key、Mock 关闭、模型未配置时，用户仍能打开工作区；进入 Chat 点示例才报错。最近工作区没有健康度。
- **建议**：Welcome 改为“3 步开始”清单：
  1. 打开工作区（已完成打勾）；
  2. 选择模型，或“使用演示模式（无需 Key）”；
  3. 和协调者描述目标。
  清单显示状态（已配置/未配置/Mock），主按钮随状态变化（“配置模型” / “开始对话”）。最近工作区加“上次打开 · 任务数 · 失败数”。
- **放置**：Welcome 常驻至完成；完成后折叠为侧栏 footer 一行“模型：已就绪 / Mock / 未配置”。
- **示例文案**：
  - 标题“先准备好，再开始”
  - 副文“模型未配置。你可以先去设置，或用演示模式体验完整流程（不会调用真实模型）。”
  - 主按钮“配置模型”；次按钮“使用演示模式”
- **验收**：无 Key 新用户 60 秒内能说出下一步；点击示例前有明确状态；不出现 raw error。

### F02 [P0] 没有解释 Router → 任务 → Run → 评审 → 记忆

- **证据**：`App.tsx:2291` 一句话；`TABS` 只有 6 个入口 `134-141`；Chat 空态只给示例 `4772-4794`；Run/Review/Memory 分属不同面板。
- **问题**：用户无法建立“我说目标 → 协调者拆任务 → 成员执行（Run）→ 评审/合并 → 记忆沉淀”的模型；`Run`/`评审`/`记忆` 成为孤立词。
- **建议**：新增“工作流”帮助内容（5 个节点 + 一句话 + 对应入口），在 Welcome 首次显示一次、可关闭；常驻入口放侧栏 `?` 和命令面板“帮助：工作流”。不要在主界面画大图。
- **放置**：首次引导卡（Welcome 内，3–5 行可折叠）+ 帮助弹窗；关闭后只在 `?`。
- **示例文案**：
  - “1 说目标：和协调者讨论；2 拆任务：协调者生成任务 DAG；3 执行：成员各跑一次任务（Run）；4 评审：合并前检查代码；5 记忆：结论沉淀到团队记忆。”
  - 每步右侧“去对话/去任务/去评审/去记忆”链接。
- **验收**：5 个新用户能复述“Run 是任务的一次执行”；能指出评审/记忆入口。

### F03 [P0] 错误文案是开发者语言，且没有恢复动作

- **证据**：`src/shared/copy.ts:146-149` 只去掉 `Error invoking remote method...`；`App.tsx:2541-2556` 只给“复制详情/关闭”；`src/kernel/service.ts:471,480,582,602` 直接抛 `member already exists`、`model is not in the configured model list`、`task not found`、`workspace not found`。
- **问题**：中文界面出现英文内部句；用户不知道是“名字重复/模型没选/工作区失效”，也不知道下一步；错误只在顶部 banner，面板内失败仍可能只显示 `失败`。
- **建议**：
  - 建错误目录：`code → {用户标题, 原因, 下一步, 是否可重试}`；已知错误走目录，未知错误显示“操作未完成”+“复制诊断信息”。
  - 常见恢复：`配置模型`（模型未配置）、`打开设置`（Key 无效）、`重命名`（成员已存在）、`重新打开工作区`（路径失效）、`重试`（网络/超时）。
  - 原始 message/stack 放“查看详情”折叠；banner 主文案 ≤ 2 行。
- **放置**：banner/面板内联常驻；详情折叠；帮助不必要。
- **示例文案**：
  - “无法创建成员：名称「Builder」已存在。换一个名称，或编辑现有成员。”
  - “模型未配置：请先在设置中选择一个模型，或启用演示模式。”
- **验收**：Top 10 错误均无英文裸句；每个错误至少 1 个恢复按钮；用户测试中 4/5 能完成恢复。

### F04 [P1] 空态未全覆盖：运行/上下文/轨迹/评审/Task VCS 仍在“裸文本”

- **证据**：`RunPanel.tsx:194-239`、`:421`；`App.tsx:5634-5638`；`ReviewSection.tsx:267`；`TeamDashboard.tsx:360-365`；`GitPanels.tsx:70-91`；`EmptyState.tsx:1-4` 已要求统一。
- **问题**：空态没有主操作，用户不知道“下一步在哪里”；`none`/`未创建` 是状态值不是解释；Context 永久“加载中”无错误/重试。
- **建议**：
  - 全部空态改用 `EmptyState`，统一“1 主 + 1 次”：
    - Run 面板：主“去任务页运行”，次“查看调度说明”；
    - 任务 Run 历史：主“运行任务”，次“查看上次失败原因”；
    - Context：加载失败显示“上下文读取失败”+“重试”+“打开日志”；空数据说明“上下文来自当前成员/模型”。
    - Review：主“去运行任务”，次“打开 Git 状态”；
    - Team 星图：主“去任务页规划”，次“刷新星图”；
    - Task VCS：`none`→“还没有创建分支/PR”，给“创建 PR”/“查看 Git 设置”。
- **放置**：空态内常驻；解释性内容可放帮助。
- **验收**：每个空态有可点击的下一步；无裸 `.empty`；Context 无永久 loading。

### F05 [P1] 导航/面板文案是实现语言，且主界面没有可见一级导航

- **证据**：`App.tsx:2498-2512` 常驻“Dock 标签切换面板；拖动标签可拆分或合并分栏”；`2438-2442`“面板”；`TABS` 只用于快捷键/标题 `134-141`。
- **问题**：用户目标词是“对话/任务/团队/记忆”，界面词是“Dock/面板/分栏/标签”；隐藏面板（运行/上下文/投票/看门狗）无稳定入口；导航提示占侧栏空间却不解决发现性。
- **建议**：
  - 主界面用“工作区导航”而非“面板”；保留 5 个核心入口（对话/任务/团队/记忆/邮箱），运行/上下文从任务上下文进入，投票/看门狗从“更多/工具”进入。
  - “拖动标签/拆分/快捷键”移到帮助或“布局”二级菜单；侧栏只留 1 行“按 ⌘K 搜索与命令”的提示（可关闭）。
  - 空态/标题用“打开运行记录”而不是“打开 Run 面板”。
- **放置**：导航常驻（用户目标词）；布局/快捷键帮助弹窗；Dock 术语仅出现在帮助。
- **验收**：首次用户能在 10 秒内找到“任务/团队/记忆”；不再需要读“Dock”才能导航。

### F06 [P1] 设置“模型”页是开发者表单，密度过高

- **证据**：`SettingsView.tsx:23-31` 7 段；`:334-374` Base URL/环境变量/API Key；`:454-483` 模型表；`:508-583` 上下文/最大输出/思考强度；`:585-604` 默认模型+保存。
- **问题**：普通用户不知道 Base URL/环境变量是什么；高级参数与基础配置同权重；“获取模型→添加→设默认→保存”四步没有引导；错误 `providerErrors` 直接显示原始 message。
- **建议**：模型页分 3 块 + 高级折叠：
  1. **连接**：供应商名称、API 地址（Base URL 括注）、密钥、Key 来源（系统环境/本地）、`测试连接`；
  2. **模型**：获取列表 → 添加 → 选择默认；空态“先获取模型”；
  3. **高级（默认折叠）**：上下文窗口、最大输出、图片、深度思考/强度；每项 1 行帮助。
  保存按钮固定在页脚；未保存离开提示。
- **放置**：基础常驻；高级折叠；Base URL/环境变量帮助 tooltip；错误用目录文案。
- **示例文案**：“API 地址：模型服务的入口地址；不确定就保留默认。”“密钥只保存在本机；也可从系统环境变量读取。”
- **验收**：非开发者 5 分钟内完成“配置供应商→添加模型→设为默认”；高级参数默认不干扰。

### F07 [P1] Mock 模式没有解释，容易被误解为真实模型/演示数据

- **证据**：`SettingsView.tsx:431-438` 仅一个“Mock 模式”复选框；`App.tsx:2516-2524` footer 显示“Mock 模式”；无说明。
- **问题**：用户可能以为 Mock 是“示例项目/缓存”，不知道它不调用真实模型、输出是模拟的；也不知道这是无 Key 的试用路径。
- **建议**：把它命名为“演示模式（不调用真实模型）”，放在首次清单和模型页顶部卡片；开启时全局 badge“演示中”；关闭时提示“将使用真实模型并计费”。
- **放置**：首次清单 + 模型设置常驻；全局 badge 常驻；详细说明帮助。
- **示例文案**：“演示模式：用模拟回复体验流程，不会调用模型、不会产生费用。适合首次试用。”
- **验收**：开启后用户能说出“不会调用真实模型”；不会把演示输出当生产结果。

### F08 [P1] 插件/MCP/Skills 是死入口 + 实现语言

- **证据**：`SettingsView.tsx:791-844`；`Placeholder` 用“当前后端还没有…”“Agent Loop 还没有…”“coming next”。
- **问题**：三个导航项占据设置主路径但不可用；文案解释的是“我们没做”，不是“你能得到什么”；英文 `coming next` 与中文混用。
- **建议**：在能力可用前**从主导航移除**，收到“实验室/即将支持”一个入口（或仅在设置页底部“即将支持”列表）；文案改为用户收益 + 当前状态 + 可订阅/查看路线图，不写后端/Agent Loop。
- **放置**：设置二级“实验室”；未开放不占一级。
- **示例文案**：“插件：把工具与界面扩展打包安装。即将支持；当前版本暂不可用。”
- **验收**：设置主导航不再有 3 个死入口；无“后端/Agent Loop/coming next”用户可见文案。

### F09 [P1] 术语混用：Run/checks/blocker/head-base/diff/quorum/decision 无首次解释

- **证据**：见 §2.1；`copy.ts:49-51`“Run 被取消/Run 超时”；`ReviewSection` 237/288/529；`PollPanel` 278/439-446；`GitPanels` 81/200。
- **问题**：用户必须懂 Git/评审/投票内部模型才能理解状态；同一概念中英混写，搜索/教学困难。
- **建议**：按 §3.2 词汇表统一；首次出现加中文括注/tooltip；状态文案用中文主词，原始值放 `title`/详情。优先改：`Run→一次执行`、`blocker→阻断项`、`checks→检查`、`quorum→通过人数/票数门槛`（按场景）、`decision→结论`。
- **放置**：主界面中文主词；首次 tooltip/帮助；原始英文只在“详情/诊断”。
- **验收**：主界面裸 `Run/blocker/checks/quorum` 数量降到 0（除帮助/详情/代码标识）；术语表进设计系统。

### F10 [P1] “记忆/黑板/备忘录/归档审批”关系不清

- **证据**：`MemoryWorkbench.tsx:700-708` 领域 chips、`:735-739`“还没有记忆条目”、`:886`“该成员还没有备忘录”、`:950`“没有待归档提案”；`App.tsx:4374-4382` 黑板领域空态。
- **问题**：面板叫“记忆”，内部叫“黑板/备忘录/归档”；用户不知道“发布记忆条目”会进哪个板、谁可见、归档审批意味着什么。
- **建议**：顶层叫“团队记忆”，三个 tab 用“共享黑板 / 个人备忘录 / 归档建议”；空态分别解释“团队共享/仅该成员/待你审批”；发布按钮写“发布到共享黑板”而非泛化“发布记忆条目”。
- **放置**：Tab/按钮常驻；治理规则帮助；归档弹窗说明后果。
- **验收**：用户能说出三个 tab 的差异；发布前知道可见范围；归档审批有明确“批准后会发生什么”。

### F11 [P1] 评审摘要暴露 Git 内部字段，缺少“我该做什么”

- **证据**：`ReviewSection.tsx:237` `head/base/mode`；`:288` `审批 1/1 · blocker`；`:317` 二进制；`:364-380` 200 行分页；`:529` 长条件句。
- **问题**：普通用户不理解 head/base/diff/approval；主按钮禁用原因是一长串技术条件；空态没有“去运行/去 Git”。
- **建议**：摘要层只显示“变更 3 个文件 · 2 条阻断项 · 待你评审/已通过/要求修改”；`head/base/diff/approval` 放“详情”展开或 tooltip；禁用原因改为“还有 2 条阻断项未解决”并给“查看阻断项”按钮；空态给“去运行任务/打开 Git 状态”。
- **放置**：摘要常驻；内部字段折叠；阻断项列表常驻。
- **验收**：非 Git 用户能说出“为什么不能通过”；能从空态走到下一步。

### F12 [P2] 投票/看门狗/Git 高级词的帮助与中文优先

- **证据**：`PollPanel.tsx:278,345,439-446,460`（quorum/decision）；`WatchdogPanel.tsx:106-129,201-224`（handoff/hold/fallback）；`GitPanels.tsx:81,200,210-222`（checks/waived）；`PollPanel` 创建表单 `595-743`。
- **问题**：这些面板默认关闭/低频，出现时却直接使用英文/运维词；缺少“这是什么/我该做什么”的第一步。
- **建议**：
  - 投票：字段标签“通过门槛（票数/百分比）”“法定人数（quorum）”；结果“投票结论（decision）”；创建表单下 1 行“关闭后生成结论并写入共享黑板”。
  - 看门狗：面板顶部一句“监控预算与卡住的执行；hold=暂停该任务，handoff=交接摘要，fallback=换模型重试”；只在帮助展开。
  - Git：`checks`→“合并前检查”，`waived`→“已豁免检查”；豁免原因输入旁说明“会记录审计，谁批准的”。
- **放置**：字段内联 helper + 帮助；不要在主界面写长解释。
- **验收**：用户能正确解释 quorum/decision/checks waiver 的含义；高级词均有中文锚点。

## 6. 设置页信息密度建议（逐段）

| 段 | 保留常驻 | 折叠/高级 | 说明位置 | 备注 |
|---|---|---|---|---|
| 模型 | 供应商名、API 地址、密钥、模型列表、默认模型、保存 | 上下文/最大输出/图片/思考强度 | 字段下 1 行 + tooltip | 加“测试连接”；Key 来源徽标；错误目录 |
| 翻译 | 启用、来源、模型、目标语言 | 计费/隐私说明 | 字段下 1 行 + 帮助 | “思考过程”而非“思考机翻源” |
| Git | Provider、基线分支、合并方式、自动合并 | worktree 容量、checks 超时、取消保留 | 场景化 helper + Git 帮助 | 危险开关加影响说明；`checks` 中文化 |
| 插件/MCP/Skills | 不占一级 | 收到“实验室/即将支持” | 一页说明 | 当前不可用，不展示假控件 |
| 团队 | 默认模型、成员概览 | 成员编辑跳转 | 1 行说明与团队页区别 | 避免重复编辑入口 |

**统一规则**：每段最多 1 个主标题 + 1 句说明；字段标签中文优先；高级项默认折叠；保存按钮固定；未保存离开提示；错误就地显示。
