## 3. 常驻 / 二级 / 低频的裁决

### 3.1 必须常驻主界面的最小信息集（P0 范围）

只保留“用户随时要看、会改变下一步、隐藏会误操作”的信息：

| # | 常驻信息 | 位置 | 状态/数据 | 为什么必须常驻 |
|---|---|---|---|---|
| S1 | 工作区身份 + 就绪度 | 侧栏顶部/一行 | 名称/路径、模型/Key/Mock、成员数 | 跨 7 步的主语；不知道模型就绪会白等/报错 |
| S2 | 一级入口 | 侧栏 rail（不替代 Dock tabs） | 对话/任务/团队/记忆/邮箱；打开态/待办 badge | 隐藏面板无法发现；命令面板不能是唯一入口 |
| S3 | 当前阶段 + 唯一下一步 | WorkflowRail 紧凑条 + 主面板顶部 | 讨论→计划→运行→评审→交付→记忆；当前 stage + 1 主 CTA | 用户不必自己记流程/找面板 |
| S4 | NeedsMe 汇总 | rail badge + 顶部短条 | 失败、阻塞、待评审、待合并、告警、预算超限 | 跨任务安全/状态；侧栏折叠时也必须可见 |
| S5 | 当前任务/上下文 | 任务面板头部/面包屑 | 当前任务、Run、来源（Chat/Team/Tasks） | 讨论—任务—运行之间不迷路 |
| S6 | 关键错误/恢复 | 顶部 inline banner（非仅 toast） | 错误摘要 + 1 个恢复动作 + 详情 | 数据丢失/阻塞必须可持续，不仅 5s |
| S7 | 主输入（Chat） | Chat 面板 composer | 模型/权限/FT/上下文 chip | 主流程起点，不能只靠进入 Chat 才知道配置 |

> **常驻原则**：只放“状态 + 入口 + 下一步”，不放长解释、长列表、历史详情、内部字段。S1–S7 可以合并为视觉上的一条 **Shell 工作条**（侧栏 rail + 顶栏 WorkflowRail + NeedsMe），不是新增一个页面。

### 3.2 默认收起、按钮/面板打开（P1/P2 范围）

| 内容 | 当前问题 | 裁决落位 | 打开方式 |
|---|---|---|---|
| Runs/完整监控 | 默认关闭、无 route、与 RunHistory 重复 | **二级面板**（默认收起） | 任务 Runs tab / “监控”入口 / `?run=` |
| Context | 默认关闭、无 route 易迷路 | **二级面板** | 任务/对话“上下文”按钮，保留返回源 |
| Polls | 默认关闭、无 route，发起后失联 | **二级面板 + 结果入口** | 任务/记忆发起后打开并保留计数 |
| Watchdog/预算详情 | 技术命名、默认关闭 | **二级面板**；仅预算/告警数常驻 topbar | topbar 数字 / NeedsMe |
| Review diff / VCS | 长内容、在任务详情底部 | **任务内二级 tab** | Task Workspace → Review / Deliver |
| MergeQueue | Modal 不适合比较/多次操作 | **二级面板**（全页/宽面板；Modal 只保留“确认合并”） | Team/Rail badge、`?merge=1` |
| Task history/trace | 长列表、2000 事件 | **任务 tab + 分页/增量** | Task → Runs/History |
| Memory 归档/TTL | 治理低频、但需可见待审 | **面板内 tab + badge** | Memory → 归档审批 |
| Settings | 7 段长 Modal、无 dirty、占位 | **二级面板/全页路由 + 分组/高级折叠**；短期至少 dirty guard | ⚙ / `#/settings` |
| 帮助/术语/快捷键 | 解释性长文 | **帮助弹窗 + 首次卡**，不常驻 | `?` / 命令面板 / 侧栏一次提示 |

### 3.3 不应出现在主流程的低频配置

- Provider Base URL、环境变量、API Key、上下文窗口、最大输出、思考强度：**设置 → 模型 → 高级折叠**，只在“配置/诊断”出现。
- 插件/MCP/Skills 未实现段：**“实验室/即将支持”**，不占一级导航；不显示假控件。
- Git worktree 容量、checks 超时、merge 策略、取消保留：**Settings → Git 高级**；任务内只显示状态/阻断原因。
- 预算/cooldown/handoff/hold/fallback 细节：**Watchdog/Monitor 二级面板**；主界面只留预算/告警数。
- 原始事件、trace、head/base/diff、raw error/stack、审计日志：**详情折叠**，不进主界面。
- 快捷键/Dock 拖拽/布局帮助：帮助弹窗或布局菜单，不占侧栏常驻空间。
- 邮箱线程/未读、星图 >150 全量、插件市场、多用户权限：**后置**，不在本轮主流程常驻。

### 3.4 每一层的判断准则（可直接复用）

- **常驻**：跨 2+ 连续阶段、跨任务安全/状态、隐藏会误操作、关闭后难恢复。
- **二级面板**：>1 屏、需要比较/多次操作、需要与主工作并看、值得保留滚动/选择/过滤器。
- **按钮 Modal**：≤1 屏、单决定/短表单、必须打断、关闭不需要保留比较状态。
- **帮助**：解释性/术语/快捷键/一次性引导，可关闭，不阻塞主流程。
- **反模式**：长设置、合并队列、行级评审、任务详情塞 Modal；失败/告警只放 toast/关闭面板；主入口只在 ⌘K；多个“批准”同屏。

## 4. P0 短名单（8 条，建议本轮批准）

### P0-1 窄窗 Dock/Team 自适应，保主流程可见

- **问题**：1100 默认窗口/960 侧栏拖窄时，Team 右栏仍以 right split 创建，主组 473/403 < Tasks minWidth 560，任务详情/Review/主按钮被挤压；960/900/760 打开 `#/team` 更直接裁切。
- **证据**：t180 F03 代码验算（1100 Dock 844→主组≈473；960 侧栏 180→主组≈403）；t185 P0-1 QA-07（ensurePanel 无条件 right split）；t183 R10/Q5。
- **用户影响**：窄窗/小屏无法完成运行→评审→合并，横向滚动/按钮不可点。
- **工程影响**：DockShell variant/ensurePanel/minWidth、侧栏自动折叠、布局存档兼容；不改变 1440 比例。
- **成本**：M。
- **落位**：Shell + Dock 布局守卫（不是新面板）；`single` 强制 Team `within`/tab，主组 clamp，必要时侧栏折叠。
- **验收**：960/900/760 ×（默认、`#/team`、Review）无横向滚动，发送/批准/合并可点；1440/1100 布局不变。
- **来源**：t180 F03；t185 P0-1；t183 R10。

### P0-2 可见的一级导航 + 隐藏面板可发现

- **问题**：主导航是 Dock tabs + ▦ 菜单 + ⌘K；无固定侧栏一级导航；Runs/Context/Polls/Watchdog 默认关闭且部分无 route；关闭后无 badge/状态。
- **证据**：t180 F01/F12；t181 F3；t184 F05；t185 P2（route）；t179 §1.1。
- **用户影响**：新用户不知道功能存在；关闭面板=消失；⌘K 从第二入口变成唯一入口。
- **工程影响**：新增 rail/侧栏分组（保留 Dock tab 为组内切换）、route/hash、状态 badge、旧布局迁移；需避免与 Dock 双重导航。
- **成本**：M。
- **落位**：常驻侧栏 rail；Dock 保留为工作区/分栏；低频面板进“更多/工具”。
- **验收**：新用户 10 秒内找到对话/任务/团队/记忆；关闭 Runs/Poll/Context 后仍能从 rail/route 恢复；键盘/读屏可命名。
- **来源**：t180 F01/F12/F15；t181 F3/F10；t184 F05；t185 P1-6/P2。

### P0-3 WorkflowRail + NeedsMe：单一“当前阶段/下一步/待我处理”

- **问题**：没有常驻阶段；失败、阻塞、待评审、待合并、告警、预算分散 5+ 表面；侧栏折叠后 failed pill 消失。
- **证据**：t181 F3/F7/F8；t180 F02；t184 F02；t185 P1-5；t179 Step 4。
- **用户影响**：用户需要巡面板；不知道下一步；异常漏处理。
- **工程影响**：聚合器（任务/Run/Review/Merge/Watchdog 事件→NeedsMe 条目）、唯一 CTA 映射、rail badge；状态源仍由现有快照/事件提供，需避免新事实源。
- **成本**：M–L（先做 badge + CTA，再做完整 inbox）。
- **落位**：常驻 WorkflowRail 紧凑条 + NeedsMe badge/短列表；详细列表在二级“需要我处理”面板（可展开，不默认占屏）。
- **验收**：失败/阻塞/评审/合并/告警均有单一条目 + 定位 + 下一步；完整周期表面切换 ≤2（讨论→计划→运行→评审→合并→记忆各段≤2）。
- **来源**：t180 F02；t181 F3/F7/F8；t184 F02；t185 P1-5。

## 9. 验收与度量（最终报告/实现任务用）

### 9.1 短名单级验收

1. **P0 全部**：8 条均有可复现验收句（§4）；实现后必须通过 1440/1100/960/900/760 视口矩阵 + 键盘脚本 + 异常矩阵（t185 §6）。
2. **主流程表面数**：目标→首任务运行 ≤2 表面；任务→评审→合并 ≤2 表面；讨论→计划不重输。
3. **发现性**：新用户 10s 内找到对话/任务/团队/记忆；关闭辅助面板后可从 rail/route 恢复。
4. **唯一动作**：任务详情每状态只有一个 primary；三个“批准”文案/作用域可区分；未通过 review 不能意外 merge。
5. **注意力**：失败/阻塞/待评审/合并 blocked/告警/预算均有 NeedsMe 条目 + 定位 + 下一步；无“只在 toast/关闭面板”的关键状态。

7. **性能**：t183 真机基线（长聊天流式、长任务事件、200 任务星图、大 diff、窄窗多面板）；P0-8 的 R1–R3 完成后再评估 R4–R7。
8. **可访问性**：Tab-only 完整走查；skip link/composer label/tabs/resizer/review/toast 断言；200% 无裁切。
